## 5. Authentication, student data and security

The code under `src/google-auth.ts` contains the **public**, intentionally publishable Supabase key and project URL. This is **not a service-role secret leak**. OAuth callback parses access/refresh tokens from URL hash, saves session including refresh token under `localStorage['litlabSupabaseSession']`, and removes callback hash with `history.replaceState`. XSS/session theft, storage retention and disclosure therefore require a security/privacy review, but no attack was performed or demonstrated. Google and account page escape user display strings before injecting the reviewed account HTML; this mitigates that particular DOM injection concern, not a complete sitewide XSS certification.

`src/account-center.ts` opts in **six legacy English progress localStorage keys** for manual Supabase backup/restore; BioLab `litlab:biology:preferences:v1` and `litlab:biology:progress:v1` are **not in that allowlist**. Explicit student explanation and tested data retention/preservation are required before claiming BioLab work backs up with signed-in LitLab accounts.

Live Supabase public catalog: **31 ordinary public tables**, all with RLS enabled; profile/progress SELECT/INSERT/UPDATE policies require `auth.uid()=user_id` and authenticated role, supporting access isolation on those paths. Some 21 public tables have no standard RLS policies and therefore deny ordinary direct data operations; their absence of policies is **not** a leak by itself. A profile role-protection trigger prevents direct `contributor_role` and specialization edits for ordinary database roles.

Important residual security review:
1. `litlab_progress` and `litlab_profiles` table privileges include broadly granted SQL operations including **TRUNCATE** and **TRIGGER**. RLS does **not** apply to PostgreSQL TRUNCATE, although no public REST route or exploit was demonstrated. Least-privilege grant review required.
2. Supabase Security Advisor returned **9 anon-executable** and **80 authenticated-executable** SECURITY DEFINER function warnings. Examined promotion evidence helper functions check `auth.uid()` and application ownership; some page/session telemetry RPCs intentionally accept anon. These need per-function authorization/abuse/retention review, not a blanket claim of unsafe functions.
3. No policy or recorded evidence verifies configured deletion/retention rights, rate limits, audit-log visibility or how analytics session identifiers are expired. No personal student data were accessed in this audit.

## 11. Independent current rights-holder permission policies (verified 2026-10-18)

The source-document copyright pages above were additionally cross-checked against **current public rights-holder guidance**, not merely past project handoffs:

- **IB policy updated 19 February 2026:** [Rules for use of IB Intellectual Property](https://ibo.org/terms-and-conditions/intellectual-property/) expressly require consent to reproduce IB content by an independent third party, including student-made online educational resources. The [IB licensing policies](https://ibo.org/become-an-ib-school/ib-publishing/licensing/licensing-policies/) specify **that IB does not grant permission/licence for IB materials on a publicly accessible website**; a special disclaimer does not supersede that exclusion. Consequently the safe public-BioLab option is **original explanations and wholly independently drawn graphics** using curricular facts, without reproducing copyrighted IB text, figures, programme models, trademarks or other protected presentation. Refer any proposed exceptional reproduction to IB directly; do not presume permission would be granted.
- **Hodder/Hachette:** Current [Hachette Learning Rights and Permissions](https://www.hachettelearning.com/rights-and-permissions) requires a permission request via **PLS Clear** using ISBN/title and notes multi-week processing; [Hachette UK illustration/photo guidance](https://www.hodder.co.uk/landing-page/hachette/contact-us-huk-v2/) explains some figures require **the illustrator's or photographer's direct approval** where separately owned. A book publisher's approval alone is not necessarily sufficient for a credited third-party illustration.
- **Drawing handout:** No verified licensed publication owner or online terms were found in the supplied 10-page handout. The visible `NOTEWORTHY SCIENCE MARIER` watermark is a provenance clue **not** authorization. The source must be independently identified and separately permissioned if copying is contemplated.
- **Authentic image source:** [CellProfiler official HT29 example](https://cellprofiler.org/examples) confirms the existence/type of the sample source; the *specific CC0 claim* comes from the prior specialist's upstream ExampleHuman README and permission discussion and remains subject to item-level grant review. PLOS figure CC BY 4.0 must include credit and modality/magnification context.

These rights-holder links and the user-supplied publication notices strengthen **NO-GO for reproduced material**. They do **not** constitute a legal finding that the existing 160 asserted original vectors violate rights.
